说明：
- 端到端 = 判断 + （判定要存时）Flash(low) 生成 description/content；jev 行即“Jev 判断 + Flash 生成”的混合系统。

- 类型 / Tag / 优先级只在 gold 判定需要存储的用例上统计；召回类型 F1 只在 gold 有相关 memory 的用例上统计。
- 命中率：gold 有相关 memory 时至少召回一条正确的比例；干净率：gold 无相关 memory 时什么都没召回的比例。
- 成本：Jev $0.042/M 输入；Flash $0.3/M 输入、$1.2/M 输出（高峰、未命中缓存）。

## 结论（2026-10-02，jev-1.13.0 vs deepseek-flash / DeepSeek-V4.1-Flash）

**速度**
- 写入判断 p50：Jev 478ms，Flash low 2216ms、high 1931ms，Jev 快约 4–4.6 倍；p95 分别为 1.4s 和 4.3–4.4s。
- 召回（判断 + 相关性排序两次调用）p50：Jev 921ms，Flash 5.5–6.3s，快约 6–7 倍；p95：Jev 1.09s，Flash 17.7–25.6s，快 16–23 倍。Jev 的尾延迟非常稳定。
- 写入端到端（含 Flash 生成内容）p50：Jev 2.7s，Flash 4.3–4.5s。生成内容占了大头，生产环境中可以把生成异步化，同步路径只剩 Jev 判断。

**成本**（每 1k 次）
- 写入判断：Jev $0.044，Flash $0.49–0.52，便宜约 11–12 倍。
- 召回：Jev $0.12，Flash $1.8–2.4，便宜约 15–20 倍。

**质量**
- 存储判断：三者都是 1.00，存在天花板效应。原因是数据集剔除了 5 条歧义样本，留下的都是界线清楚的用例。要拉开差距，需要补充边界样本。
- 召回门：Jev Acc 0.94、AUC 0.97，与 Flash 的 0.92–0.93 持平，略好。
- 召回 memory F1：Jev 0.78，Flash 0.76–0.79，持平。命中率 Jev 0.92 略低于 Flash 的 0.97。
- 类型：写入时 Jev 0.93，Flash low 0.94；召回类型 F1 三者都在 0.65 左右。
- Jev 偏弱的地方是 tag 和优先级。
  - Tag F1 0.80，Flash 是 0.86。Jev 倾向多打 tag：P 0.68 / R 0.96。离线把阈值调到 0.6 后 F1 为 0.83，但这是在测试集上调的，有过拟合风险。
  - 优先级 Acc 0.83，Flash 是 0.94。Jev 的错误全部是把 medium 判成 high，属于偏保守的错误。
- Flash high 和 low 的质量相当，但更慢更贵，不值得用在这类判断上。

**中文**
- Jev 中文写入类型 Acc 0.89，英文 0.96；中文召回命中率 0.90，英文 0.94。有轻度下降，与官方"CJK 较弱"的说法一致，但不影响可用性。
- 召回门和 memory F1 中英文没有差别。

**公共瓶颈**
- 候选覆盖率只有约 0.90：按类型和 tag 过滤时，有约 10% 的相关 memory 被提前丢掉，三种配置都受影响，这限制了召回上限。
- 记忆库较小（36 条）时，可以直接对全部 memory 做相关性 Noul（speculative fan-out），跳过过滤。

**偏差提示**
- gold 由 DeepSeek Pro 盲标注，对 Flash 可能有同源优势。
- 样本量较小：写入 43×2、召回 48×2。

## 第二轮结论（修订第一轮）

**1. 换成最快的 LLM 对照（Flash 关闭 thinking），速度差距缩小到约 2.5–3 倍，但对照组的质量也明显下降。**
- 延迟地板：用最简单的请求、连接已建立时测，Jev p50 433ms，flash-nothink p50 1105ms。Jev 带 15 道题的写入判断是 421ms，说明它的延迟几乎全是固定开销，题目数量影响很小（实测 64、150、300 道 Noul 分别为 629、710、875ms）。
- flash-nothink 和 Jev 的速度差距是：判断 2.7 倍，召回 2.6–2.8 倍，大库召回 p95 是 2.6 倍。成本差距是 5 倍。
- flash-nothink 召回记忆的准确率在三个数据集上都是最差的：P 0.54–0.61，F1 0.45–0.65。边界写入题的优先级准确率只有 0.59。
- 所以"又快又准"的 LLM 选项并不存在：Flash low 准，但比 Jev 慢 6–12 倍，p95 慢 20–30 倍；flash-nothink 快一些，但不准。

**2. 边界样本暴露了 Jev 的真实短板：依赖上下文的写入判断。**
- 边界写入的存储判断准确率：Jev 0.84，flash-low 0.96。Jev 精确率 0.98、覆盖率 0.80，偏向漏存。
- 调阈值无效：从 0.5 调到 0.1，准确率一直在 0.80–0.84 之间。
- 漏判集中在两类：一是"Scratch that, the trip moved to December"这种要结合上文才能理解的更正，也就是官方文档写明的 indirection 弱点；二是"明天看牙"这类短期但重要的状态。
- 类型（0.82 vs 0.93）和优先级（0.71 vs 0.79）也落后于 flash-low。

**3. 召回是 Jev 的主场，记忆库越大优势越明显。**
- 大库限制 Top-5 时，Jev 的 F1 是 0.60，在所有配置里最高；flash-low 0.53，flash-nothink 0.45。Jev 的 P@5 是 0.73，flash-low 0.65。原因是 Jev 输出连续的相关性概率，可以排序；LLM 只能给出"相关 / 不相关"。
- 不限制条数时，flash-low 的 F1 是 0.67，Jev 0.61。Top-5 的理论覆盖上限只有 0.63，因为 gold 平均有 3.6 条相关记忆，最多一题有 32 条。
- 大库召回延迟：Jev 0.92s / 1.3s，flash-low 11s / 40s（p50 / p95）。
- 小库和边界集上，jev-fanout 与 flash-low 的 F1 只差 0.02（0.80 vs 0.82，0.75 vs 0.77），在两轮之间约 ±0.03 的波动范围内，可以视为持平。

**4. jev-fanout（跳过过滤，对全部记忆判断相关性）在小库上值得作为默认。**
- 候选覆盖率从 0.86–0.90 提升到 0.96–0.97；小库和边界集的 F1 分别提升 0.01 和 0.04，延迟只增加 20–30ms。
- 在 286 条的大库上，F1 没有提升（0.59 vs 0.60），成本却高出约 50%。原因是候选太多，Top-5 截断把覆盖率的收益抵消了。

**5. 中文**：第二轮中，Jev 中英文的召回 F1 差距不超过 0.03。写入类型准确率中文低约 0.07（0.89 vs 0.96），与第一轮一致。

**修订后的架构建议**
- **召回路径**：用 Jev。记忆库小于约 100 条时用 fan-out；更大的库先按类型和 tag 过滤，再把 Top-K 调大或改用阈值。
- **写入路径**：先用 Jev 实时做第一道门，只要 store_prob 达到 0.5 就写入（精确率 0.98，基本不会误存）。然后在已经异步运行的 Flash 生成环节，对 Jev 判为不存、但概率处在中间区间的消息做复核，同时修正类型和优先级。这样漏存问题可以由 LLM 兜底，而用户的同步等待只有 Jev 的约 0.4s。
- Flash high 和 flash-nothink 在这个场景里都不推荐使用。

**仍然存在的局限**：只有一个人设；gold 来自 DeepSeek Pro；大库 gold 偏宽（有一题 32 条相关）；本机通过代理访问两家 API，延迟的绝对值不能直接外推。
